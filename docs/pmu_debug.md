# Arm RMM ACS PMU and Debug Testcase checklist
-----------------------------------------------------

This document presents the mapping of the rules in the RMM specification to the
test cases and the steps followed in the tests. This also provides the information
about the test coverage scenarios that are implemented in the current release of
ACS and the scenarios that are planned for the future releases.


| Test Number | Test Name             | Test Assertion                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Test Steps                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Validated by ACS |
| ----------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| 1           | pmu_overflow | On REC exit, `pmu_ovf_status` reports the level of the Realm-assigned PMU overflow interrupt. After the Realm handles the virtual interrupt and clears the overflow, the next REC exit reports it inactive. | 1. Check PMU support and enable the Host PMU interrupt.<br>2. Create and enter a PMU-enabled Realm.<br>3. In the Realm, set event counter 0 near overflow and enable its overflow interrupt.<br>4. Check that the first REC exit is an IRQ exit with `RMI_PMU_OVERFLOW_ACTIVE`.<br>5. Disable the Host physical PMU PPI, inject the virtual PMU interrupt through the Host `ICH_LR<n>_EL2` register, and re-enter the REC.<br>6. In the Realm, handle the interrupt, clear the overflow, and return by Host call.<br>7. Check the Host-call exit and `RMI_PMU_OVERFLOW_NOT_ACTIVE`. | Yes              |
| 2           | cmd_realm_create | Requesting a number of PMU counters which is different from the number of PMU counters available causes RMI_REALM_CREATE to fail.<br>Requesting a number of breakpoints which is different from the number of breakpoints available causes execution of RMI_REALM_CREATE to fail.<br>Requesting a number of watchpoints which is different from the number of watchpoints available causes execution of RMI_REALM_CREATE to fail.  | 1. Pass the PMU counters more than the supported number to RMI_REALM_CREATE ABI and check for error status code. <br>2. Pass the breakpoints count more than the supported number to RMI_REALM_CREATE ABI and check for error status code. <br>3. Pass the watchpoints count more than the supported number to RMI_REALM_CREATE ABI and check for error status code.<br>                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Yes              |
| 3           | debug_feature_discovery | RMI_FEATURES(0) reports the implemented breakpoint and watchpoint counts through NUM_BPS and NUM_WPS. | 1. Read ID_AA64DFR0_EL1.<br>2. If BRPs or WRPs is 0xF, obtain the extended value from ID_AA64DFR1_EL1.<br>3. Call RMI_FEATURES with index 0.<br>4. Compare NUM_BPS[19:14] and NUM_WPS[25:20] against the architectural values.<br>5. Fail on any mismatch. | Yes |
| 4           | pmu_assigned_state | Realm-assigned PMU state is saved on REC exit and restored on REC entry. | 1. Realm writes distinctive counter, event-type, and enable state.<br>2. Exit to Host.<br>3. Host replaces the physical state.<br>4. Re-enter and verify the Realm state is restored from the REC. | Yes |
| 5           | pmu_host_retained | Host-retained counters are disabled during Realm execution. | 1. Host enables a counter outside the Realm-assigned range.<br>2. Enter Realm.<br>3. Verify its enable bit reads zero.<br>4. Verify Host enable state is restored after exit. | Yes |
| 6           | pmu_cycle_counter | Conditional processor Cycle Counter preservation and Realm counting. | 1. With Host cycle counting disabled, save a Realm value.<br>2. With Host counting enabled, verify the Host value is preserved and advances in Realm.<br>3. Disable Host counting and verify the saved REC value is restored. | Partial: RMM-only counting intervals are not externally observable. |
| 7           |  | Realm-assigned PMU state is scrubbed before RMM restores the Host PMU context on REC exit. | ACS out of scope: the restored Host context masks the intermediate scrubbed PMU state before control returns to ACS. | No |
