# Arm RMM ACS PSMMU Testcase checklist
-----------------------------------------------------

This document presents the mapping of the rules in the RMM specification to the
test cases and the steps followed in the tests. This also provides the information
about the test coverage scenarios that are implemented in the current release of
ACS and the scenarios that are planned for the future releases.

| Test Number | Test Name | Test Assertions | Test Approach | Validated by ACS |
| --- | --- | --- | --- | --- |
| 1 | psmmu_activate_sro_donate | RMI_PSMMU_ACTIVATE follows the SRO memory donation flow when activation requires RMM-owned memory. | 1. Check DA support and read PSMMU information with RMI_PSMMU_INFO.<br>2. Allocate the PSMMU parameter page.<br>3. Call RMI_PSMMU_ACTIVATE with ATS enabled. If activation requires DPT state, create the DPT L0 and retry. If ATS is not accepted on the platform, retry with ATS disabled.<br>4. Complete any RMI_INCOMPLETE operation using the SRO donation helper and verify the operation completes with RMI_SUCCESS.<br>5. Cleanup by deactivating the PSMMU if activation succeeded. | Yes |
| 2 | psmmu_deactivate_sro_reclaim | RMI_PSMMU_DEACTIVATE follows the SRO memory reclaim flow when deactivation returns memory owned by the PSMMU object. | 1. Check DA support and read PSMMU information with RMI_PSMMU_INFO.<br>2. Activate the PSMMU using the common PSMMU activation preparation flow.<br>3. Call RMI_PSMMU_DEACTIVATE.<br>4. Complete any RMI_INCOMPLETE operation using the SRO reclaim helper and verify the command completes with RMI_SUCCESS.<br>5. Cleanup remaining PSMMU state if deactivation did not complete. | Yes |
| 3 | psmmu_st_l2_create_sro_donate | RMI_PSMMU_ST_L2_CREATE follows the SRO memory donation flow when creating a Level 2 Stream Table. | 1. Check DA support and read PSMMU information with RMI_PSMMU_INFO.<br>2. Activate the PSMMU using the common PSMMU activation preparation flow.<br>3. Call RMI_PSMMU_ST_L2_CREATE for the test SID.<br>4. Complete any RMI_INCOMPLETE operation using the SRO donation helper and verify RMI_SUCCESS.<br>5. Call RMI_PSMMU_ST_L2_CREATE again for the same SID and verify the duplicate create is rejected.<br>6. Cleanup by destroying the L2 Stream Table and deactivating the PSMMU. | Yes |
| 4 | psmmu_st_l2_destroy_sro_reclaim | RMI_PSMMU_ST_L2_DESTROY follows the SRO memory reclaim flow when destroying a Level 2 Stream Table. | 1. Check DA support and read PSMMU information with RMI_PSMMU_INFO.<br>2. Activate the PSMMU and create the L2 Stream Table for the test SID.<br>3. Call RMI_PSMMU_ST_L2_DESTROY.<br>4. Complete any RMI_INCOMPLETE operation using the SRO reclaim helper and verify RMI_SUCCESS.<br>5. Call RMI_PSMMU_ST_L2_DESTROY again for the same SID and verify the duplicate destroy is rejected.<br>6. Cleanup by deactivating the PSMMU. | Yes |
| 5 | dpt_l0_create_sro_donate | RMI_DPT_L0_CREATE follows the SRO memory donation flow when creating the Level 0 DPT. | 1. Check DA support and prepare an assigned-device context using the common PSMMU SRO setup.<br>2. Call RMI_DPT_L0_CREATE.<br>3. Complete any RMI_INCOMPLETE operation using the SRO donation helper and verify RMI_SUCCESS.<br>4. Call RMI_DPT_L0_CREATE again and verify the duplicate create is rejected with RMI_ERROR_INPUT.<br>5. Cleanup by destroying any DPT state and tearing down DA objects. | Yes |
| 6 | dpt_l0_destroy_sro_reclaim | RMI_DPT_L0_DESTROY follows the SRO memory reclaim flow when destroying the Level 0 DPT. | 1. Check DA support and prepare an assigned-device context using the common PSMMU SRO setup.<br>2. Create the DPT L0 using RMI_DPT_L0_CREATE.<br>3. Call RMI_DPT_L0_DESTROY.<br>4. Complete any RMI_INCOMPLETE operation using the SRO reclaim helper and verify RMI_SUCCESS.<br>5. Call RMI_DPT_L0_DESTROY again and verify the duplicate destroy is rejected with RMI_ERROR_INPUT.<br>6. Cleanup DA objects. | Yes |
| 7 | dpt_l1_create_sro_donate | RMI_DPT_L1_CREATE follows the SRO memory donation flow when creating a Level 1 DPT for an assigned-device address range. | 1. Check DA support and prepare an assigned-device context using the common PSMMU SRO setup.<br>2. Create the DPT L0 using RMI_DPT_L0_CREATE.<br>3. Choose the L1 DPT address by aligning the assigned device non-coherent address range down to the DPT L1 alignment.<br>4. Call RMI_DPT_L1_CREATE for that address.<br>5. Complete any RMI_INCOMPLETE operation using the SRO donation helper and verify RMI_SUCCESS.<br>6. Call RMI_DPT_L1_CREATE again for the same address and verify the duplicate create is rejected with RMI_ERROR_INPUT.<br>7. Cleanup DPT and DA state. | Yes |
| 8 | dpt_l1_destroy_sro_reclaim | RMI_DPT_L1_DESTROY follows the SRO memory reclaim flow when destroying a Level 1 DPT. | 1. Check DA support and prepare an assigned-device context using the common PSMMU SRO setup.<br>2. Create the DPT L0 and L1 for the assigned device non-coherent address range.<br>3. Call RMI_DPT_L1_DESTROY for the L1 address.<br>4. Complete any RMI_INCOMPLETE operation using the SRO reclaim helper and verify RMI_SUCCESS.<br>5. Call RMI_DPT_L1_DESTROY again for the same address and verify the duplicate destroy is rejected with RMI_ERROR_INPUT.<br>6. Cleanup DPT and DA state. | Yes |
| 9 | dpt_l0_create_alignment | RMI_DPT_L0_CREATE rejects invalid SRO donation memory that does not satisfy the requested alignment. | 1. Check DA support and prepare an assigned-device context using the common PSMMU SRO setup.<br>2. Call RMI_DPT_L0_CREATE and wait for an SRO donation request.<br>3. Intentionally respond to the donation request with a misaligned memory range descriptor.<br>4. Verify RMI_OP_MEM_DONATE rejects the donation with RMI_ERROR_INPUT.<br>5. Continue the original SRO operation so the RMM can complete or cancel the operation cleanly.<br>6. Pass only if the DPT L0 donation request was observed and the misaligned donation was rejected. | Yes |
| 10 | psmmu_interrupt_handling | RMI_PSMMU_IRQ_NOTIFY reports PSMMU interrupt events and clears pending wired interrupts. | 1. Check DA support and read PSMMU information with RMI_PSMMU_INFO.<br>2. Skip if the PSMMU reports MSI interrupt configuration, because this test requires platform wired IRQ triggering.<br>3. Activate the PSMMU with ATS disabled.<br>4. Call RMI_PSMMU_IRQ_NOTIFY with no IRQ set and verify no stale event is reported.<br>5. If CMDQ-sync wired IRQ is reported, trigger the CMDQ-sync IRQ and verify notification clears it without reporting a PSMMU event.<br>6. Trigger EVENTQ and PRIQ wired interrupts and verify RMI_PSMMU_IRQ_NOTIFY reports RMI_PSMMU_IRQ_EVENT_PSMMU.<br>7. Trigger GERROR wired interrupt and verify RMI_PSMMU_IRQ_NOTIFY reports RMI_PSMMU_IRQ_EVENT_ERROR.<br>8. Cleanup by deactivating the PSMMU. | No |
