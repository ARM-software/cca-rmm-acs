# Arm RMM ACS GIC Testcase checklist
-----------------------------------------------------

This document presents the mapping of the rules in the RMM specification to the
test cases and the steps followed in the tests. This also provides the information
about the test coverage scenarios that are implemented in the current release of
ACS and the scenarios that are planned for the future releases.


| Test Number | Test Name | Test Assertion | Test Steps | Validated by ACS |
| ----------- | --------- | -------------- | ---------- | ---------------- |
| 1 | gic_rec_entry_gic_state_preserved | RNMPBP: On REC entry, the values of the virtual GIC CPU interface state are preserved for:<br>• `ICH_HCR_EL2`<br>• `ICH_VMCR_EL2`<br>• implemented `ICH_AP0R<n>_EL2` and `ICH_AP1R<n>_EL2` registers<br>• implemented `ICH_LR<n>_EL2` registers | 1\. Create the realm and REC using the common host setup flow<br>2\. Read `ICH_VTR_EL2` to determine the implemented LR and APR counts, capped by the ACS-supported register arrays<br>3\. Clear the host virtual GIC CPU interface state<br>4\. Program known host-side values into `ICH_HCR_EL2`, `ICH_VMCR_EL2`, every implemented `ICH_AP0R<n>_EL2` and `ICH_AP1R<n>_EL2`, and every implemented `ICH_LR<n>_EL2`<br>5\. Read the programmed registers back and use those readback values as the expected baseline, so architecturally normalized fields are compared correctly<br>6\. Enter the Realm with `RMI_REC_ENTER` and let the Realm return to the Host<br>7\. Verify that all programmed `ICH_*` state still matches the baseline values<br>8\. Clear the host virtual GIC CPU interface state during cleanup | Yes |
| 2 | gic_lr_hw_rejected | RHLFRY: REC entry fails if `ICH_LR<n>_EL2.HW == 1` for any implemented value of `n`. | 1\. Create the realm and REC<br>2\. Read `ICH_VTR_EL2` to determine the implemented LR count<br>3\. For each implemented `ICH_LR<n>_EL2`, set `HW = 1` with pending, active, and pending-active interrupt states<br>4\. Execute REC enter and verify the command is rejected with `RMI_ERROR_REC` for every hardware-backed List Register encoding | Yes |
| 3 | gic_pmr_masks_irq_exit | RLNQRL: A REC exit due to IRQ is not generated for an interrupt masked by `ICC_PMR_EL1` at the time of REC entry. | 1\. Create the realm and REC<br>2\. Program a pending virtual interrupt into `ICH_LR<n>_EL2`<br>3\. Set `ICC_PMR_EL1` so that the interrupt is masked at REC entry<br>4\. Enter the Realm<br>5\. Verify that the expected Host-call exit occurs, proving that the masked interrupt did not generate an IRQ exit | Yes |
| 4 | gic_rec_exit_gic_state_preserved | RFGQXT: On REC exit, the values of the virtual GIC CPU interface state are preserved for:<br>• ICH_AP0R<n>_EL2<br>• ICH_AP1R<n>_EL2<br>• ICH_LR<n>_EL2<br>• ICH_VMCR_EL2<br>• ICH_HCR_EL2 | 1\. Create the realm and REC<br>2\. Enter the Realm with known virtual GIC CPU interface state<br>3\. Acknowledge or handle a virtual interrupt in the Realm<br>4\. Exit the Realm<br>5\. Read the physical `ICH_LR0_EL2` state through the host GIC helper and verify the LR state transitions from active to inactive as expected | Yes |
| 5 | gic_rec_exit_vgic_disabled | RVSBBS: On REC exit, `ICH_HCR_EL2.En == 0`. | 1\. Create the realm and REC<br>2\. Enter the Realm<br>3\. Exit the Realm via Host call<br>4\. Read the physical `ICH_HCR_EL2` through the host GIC helper<br>5\. Verify that `ICH_HCR_EL2.En == 0` | Yes |
| 6 | gic_sgi_sysreg_write_trap | RXRKLG: Realm write access to `ICC_ASGI1R_EL1`, `ICC_SGI0R_EL1`, or `ICC_SGI1R_EL1` results in a REC exit due to System register access. | 1\. Create the realm and REC<br>2\. Enter the Realm<br>3\. From Realm payload, write to `ICC_ASGI1R_EL1`<br>4\. Verify REC exit due to System register access<br>5\. Repeat for `ICC_SGI0R_EL1` and `ICC_SGI1R_EL1` | Yes |
| 7 | gic_trapped_icc_sysreg_access | RMMTQQ: Realm access to trapped `ICC_*_EL1` registers, except `ICC_ASGI1R_EL1`, `ICC_SGI0R_EL1`, and `ICC_SGI1R_EL1`, results in a REC exit due to System register access if the corresponding trap was set in `ICH_HCR_EL2` at REC entry. | 1\. Create the realm and REC<br>2\. Set the corresponding trap control in `ICH_HCR_EL2` at REC entry<br>3\. Enter the Realm<br>4\. From Realm payload, access a trapped `ICC_*_EL1` register other than the excluded SGI registers<br>5\. Verify REC exit due to System register access | No |
| 8 | gic_arch_timer_available | RLKNDV: Architectural timers are available to a Realm and behave according to their architectural specification. | 1\. Create the realm and REC<br>2\. Enter the Realm<br>3\. Read architectural counter values from Realm payload<br>4\. Program EL1 timer state from Realm payload<br>5\. Verify timer and counter behavior follows architectural expectations | Yes |
| 9 | gic_el2_timer_asserts | RFKCHX: If the Host has programmed an EL2 timer to assert its output during Realm execution, that timer output is guaranteed to assert. | 1\. Program the EL2 timer to fire from the Host side<br>2\. Enter the Realm<br>3\. Wait until the EL2 timer condition is met<br>4\. Verify that the timer output asserts and a REC exit due to IRQ is observed | Yes |
| 10 | gic_counter_monotonic | RRJZRP: Both the virtual and physical counter values are guaranteed to be monotonically increasing when read by a Realm. | 1\. Enter the Realm<br>2\. Read `CNTPCT_EL0` and `CNTVCT_EL0` at `t0`<br>3\. Read `CNTPCT_EL0` and `CNTVCT_EL0` again at `t1`<br>4\. Verify that the physical counter value at `t1` is greater than or equal to `t0`<br>5\. Verify that the virtual counter value at `t1` is greater than or equal to `t0` | Yes |
| 11 | gic_counter_equal | RJSMQP: A read by a Realm of either the virtual or physical counter at the same place in the instruction flow returns the same value. | 1\. Enter the Realm<br>2\. Read `CNTPCT_EL0` and `CNTVCT_EL0` from a controlled instruction sequence<br>3\. Compare the observed physical and virtual counter values<br>4\. Verify that the values match at the same point in the instruction flow | Yes |
| 12 | gic_el1_timer_irq_exit | RSVCMR: On a change in the output of an EL1 timer which requires a Realm-observable change to virtual interrupt state, a REC exit occurs. | 1\. Enter the Realm<br>2\. Program the EL1 physical or virtual timer to fire from Realm payload<br>3\. Wait until the timer condition is met<br>4\. Verify that REC exit due to IRQ occurs when virtual interrupt state must change<br>5\. Repeat for physical and virtual EL1 timers | Yes |
| 13 | gic_rec_exit_timer_state | RVWQDH: On REC exit, Realm EL1 timer state is exposed via the `RmiRecExit` object:<br>• `exit.cntv_ctl` contains `CNTV_CTL_EL0` at Realm exit<br>• `exit.cntv_cval` contains `CNTV_CVAL_EL0` as if virtual counter offset was zero<br>• `exit.cntp_ctl` contains `CNTP_CTL_EL0` at Realm exit<br>• `exit.cntp_cval` contains `CNTP_CVAL_EL0` as if physical counter offset was zero | 1\. Enter the Realm<br>2\. Program the physical EL1 timer enabled and unmasked so it expires during Realm execution<br>3\. Program the virtual EL1 timer enabled and masked with a known compare value<br>4\. Record both compare values in the shared test page<br>5\. On Host side, verify REC exit due to IRQ occurred<br>6\. Verify `exit.cntp_ctl`, `exit.cntp_cval`, `exit.cntv_ctl`, and `exit.cntv_cval` match the Realm EL1 timer state | Yes |
